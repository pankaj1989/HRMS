# Phase 1.2 — Tenancy + Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the identity foundation: real `platform.tenants`, `entity.entities` (with PAN/TAN/PF/ESI/PT statutory regs), `iam.users`, `iam.sessions`, `iam.refresh_tokens` schemas; per-schema Postgres roles replacing the P1.1 `app_role` test workaround; argon2id password hashing; JWT auth (RS256, 15-min access + 30-day refresh) with refresh-rotation reuse-detection; NestJS tenant-context middleware that opens an RLS-scoped transaction per request from JWT claims; login + refresh + logout endpoints with hard discipline (failed-login lockout, generic error messages, httpOnly Secure SameSite=Strict cookies). Deliverable: a real human can sign up → log in → load `/v1/me` → refresh token → log out, with RLS enforced end-to-end through actual auth (not test-only role).

**Architecture:** Hexagonal IAM module (`apps/api/src/modules/iam/`) with pure-TS domain (`User`, `Session`, `RefreshToken` aggregates), Drizzle adapters in `infrastructure/persistence/`, JWT signer adapter in `infrastructure/crypto/`. Real schemas in `packages/db/src/schemas/{platform,entity,iam}.ts` replacing P1.1 demo tables. Per-schema Postgres roles (`hrms_app_iam`, `hrms_app_platform`, `hrms_app_entity`) with USAGE on their schema only — defense-in-depth that closes the test-only superuser bypass. Tenant-context middleware in `apps/api/src/modules/iam/interface/middleware/tenant-context.middleware.ts` parses the access JWT, opens an RLS-scoped transaction via `withTenantContext`, attaches the request scope.

**Tech Stack:** `@node-rs/argon2` 1.8 · `jose` 5.9 (JWT/RS256) · NestJS 10 · Drizzle 0.36 · pg 8.13 · vitest 2.1 · `@testcontainers/postgresql` 10.13.

**Reference:** [Architecture design §3 (`iam`, `entity`, `platform` modules)](../specs/2026-05-01-hrms-architecture-design.md#3--bounded-contexts-modules) · [§6.2 Per-schema roles](../specs/2026-05-01-hrms-architecture-design.md#62--schema-per-bounded-context-with-isolated-postgres-roles) · [§7.1 Authentication](../specs/2026-05-01-hrms-architecture-design.md#71--authentication) · [§5 Module hexagonal pattern](../specs/2026-05-01-hrms-architecture-design.md#5--module-internal-pattern-hexagonal).

## ⚠️ Scope: what's IN, what's deferred to P1.3

### IN P1.2

- Schemas: `platform.tenants`, `entity.entities`, `entity.statutory_registrations`, `iam.users`, `iam.sessions`, `iam.refresh_tokens` — all RLS-FORCE'd, with provenance metadata
- Per-schema Postgres roles (replaces P1.1 test-only `app_role` workaround)
- Argon2id password hashing (NIST 800-63B parameters)
- JWT auth (RS256, 15-min access, 30-day refresh stored httpOnly Secure SameSite=Strict)
- Refresh rotation with **reuse detection** (revoke session family on detected reuse)
- Failed-login lockout (5 attempts in 15 min → 30-min lock)
- Generic error messages (`auth.failed` — never reveal whether email exists)
- NestJS tenant-context middleware (parses JWT → opens RLS-scoped tx → attaches scope)
- Login / Refresh / Logout / Me endpoints with full integration tests
- ADR 0004 (custom JWT vs Better Auth)

### DEFERRED to P1.3 (RBAC + MFA)

- `iam.roles`, `iam.permissions`, `iam.role_permissions`, `iam.user_effective_permissions` materialized view
- Capability tokens (compile-time-enforced authz)
- ABAC policies in `packages/contracts/policies/`
- TOTP MFA
- WebAuthn passkeys
- SMS-OTP MFA (DLT-compliant, non-admin only)
- Step-up auth for sensitive operations
- HIBP k-anonymity password check
- Device fingerprint capture
- Concurrent session limit + force-logout-all
- DPDPA consent receipts (Ed25519)
- JWKS endpoint + signing-key rotation tooling

### DEFERRED to later phases

- Tenant lifecycle state machine (Phase 4 — onboarding wizard)
- Entity lifecycle state machine (Phase 4)
- Statutory ID validators (MCA21, GSTN, IT-dept) (Phase 4 — onboarding)
- Continuous risk scoring + adaptive auth (Phase 4)
- JIT privilege elevation (Phase 4)
- OAuth2 Resource Server (Phase 4+)
- OIDC / SAML / SCIM (Phase 5)
- ReBAC / OpenFGA sidecar (Phase 4+)
- Platform admin separation (separate `platform_admin.users` schema, separate cookie domain) (Phase 5+)

import { z } from 'zod';
import fs from 'node:fs';

const AuthEnvSchema = z.object({
  JWT_PRIVATE_KEY_PATH: z.string().default('infra/secrets/jwt-private.dev.pem'),
  JWT_PUBLIC_KEY_PATH: z.string().default('infra/secrets/jwt-public.dev.pem'),
  JWT_ISSUER: z.string().default('hrms.local'),
  JWT_AUDIENCE: z.string().default('hrms.api'),
  ACCESS_TOKEN_TTL_SEC: z.coerce
    .number()
    .int()
    .positive()
    .default(15 * 60),
  REFRESH_TOKEN_TTL_SEC: z.coerce
    .number()
    .int()
    .positive()
    .default(30 * 24 * 60 * 60),
  LOGIN_LOCKOUT_THRESHOLD: z.coerce.number().int().positive().default(5),
  LOGIN_LOCKOUT_WINDOW_SEC: z.coerce
    .number()
    .int()
    .positive()
    .default(15 * 60),
  LOGIN_LOCKOUT_DURATION_SEC: z.coerce
    .number()
    .int()
    .positive()
    .default(30 * 60),
});

export type AuthEnv = z.infer<typeof AuthEnvSchema> & {
  privateKey: string;
  publicKey: string;
};

export function loadAuthEnv(source: Record<string, string | undefined> = process.env): AuthEnv {
  const parsed = AuthEnvSchema.parse(source);
  const privateKey = fs.readFileSync(parsed.JWT_PRIVATE_KEY_PATH, 'utf8');
  const publicKey = fs.readFileSync(parsed.JWT_PUBLIC_KEY_PATH, 'utf8');
  return { ...parsed, privateKey, publicKey };
}
```

-- 0004_platform_tenants
-- expand-contract phase: EXPAND
-- locks acquired: AccessShare on platform schema (negligible)
-- safe to run during business hours: yes
-- estimated duration: <1s

CREATE TABLE platform.tenants (
  id                          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  display_name                text NOT NULL,
  slug                        text NOT NULL UNIQUE,
  status                      text NOT NULL DEFAULT 'active'
    CHECK (status IN ('active', 'suspended', 'cancelled')),
  tier                        text NOT NULL DEFAULT 'standard'
    CHECK (tier IN ('trial', 'standard', 'enterprise')),

  -- Provenance metadata (spec §5.13)
  created_at                  timestamptz NOT NULL DEFAULT now(),
  updated_at                  timestamptz NOT NULL DEFAULT now(),
  created_by_request_id       uuid,
  created_by_release          text,
  created_by_actor_id         uuid,
  last_modified_by_request_id uuid,
  last_modified_by_release    text,
  last_modified_by_actor_id   uuid,

  _version                    integer NOT NULL DEFAULT 1,
  is_deleted                  boolean NOT NULL DEFAULT false
);

CREATE UNIQUE INDEX tenants_slug_unique ON platform.tenants (slug) WHERE is_deleted = false;

ALTER TABLE platform.tenants ENABLE ROW LEVEL SECURITY;
ALTER TABLE platform.tenants FORCE  ROW LEVEL SECURITY;

-- A tenant can read its own row (for tenant-admin); platform-admin queries
-- bypass RLS by connecting as a privileged role (defined in 0008).
CREATE POLICY tenant_isolation_select ON platform.tenants
  FOR SELECT
  USING (id = NULLIF(current_setting('app.tenant_id', true), '')::uuid);

-- Tenant-write requires the same isolation; platform-admin connects as
-- hrms_admin (see 0008) which has BYPASSRLS for tenant lifecycle ops.
CREATE POLICY tenant_isolation_modify ON platform.tenants
  FOR ALL
  USING       (id = NULLIF(current_setting('app.tenant_id', true), '')::uuid)
  WITH CHECK  (id = NULLIF(current_setting('app.tenant_id', true), '')::uuid);

COMMENT ON TABLE platform.tenants IS
  'Top-level customer organizations. Each row is one tenant; multiple legal entities under entity.entities link back here.';
```

import path from 'node:path';
import { afterAll, beforeAll, describe, expect, it } from 'vitest';
import { migrate } from 'drizzle-orm/node-postgres/migrator';
import { startPostgres, type RunningPg } from '../src/test-utils/postgres-container';

const TENANT_B = '22222222-2222-2222-2222-222222222222';

describe('platform.tenants', () => {

  let db: DbClient;

  beforeAll(async () => {
    pgInst = await startPostgres();
    db = createClient({ DATABASE_URL: pgInst.url });
    await migrate(db.drizzle, {
      migrationsFolder: path.resolve(__dirname, '..', 'src', 'migrations'),

    await db.execute('CREATE ROLE app_role NOLOGIN');
    await db.execute('GRANT USAGE ON SCHEMA platform TO app_role');

    await db.close();
    await pgInst.stop();

// apps/api/src/modules/iam/infrastructure/crypto/argon2-password-hasher.ts
import { hash as argonHash, verify as argonVerify, Algorithm } from '@node-rs/argon2';
import type { PasswordHasherPort } from '../../domain/ports/password-hasher.port';

// NIST SP 800-63B parameters for argon2id; tuned for ~250ms on a modern CPU.
const PARAMS = {
  algorithm: Algorithm.Argon2id,
  memoryCost: 64 * 1024, // 64 MiB
  timeCost: 3,
  parallelism: 4,
};

export class Argon2PasswordHasher implements PasswordHasherPort {
  async hash(plain: string): Promise<string> {
    return argonHash(plain, PARAMS);
  }

  async verify(hash: string, plain: string): Promise<boolean> {
    try {
      return await argonVerify(hash, plain);
    } catch {
      return false;
    }
  }
}

The service:

1. Given a presented refresh token (raw), HMAC-hash it.
2. Look up `iam.refresh_tokens` by hash.
3. If not found → throw `InvalidRefreshToken`.
4. If `consumed_at` is set (token was already consumed once) → **mark entire session family revoked**, throw `RefreshReuseDetected`.
5. Otherwise mark current as consumed; create new session row (parent = current); create new refresh token (random 32 bytes, hashed for storage); return `{ accessJwt, newRefreshToken (raw), expiresAt }`.

## Task 11 — Login command + handler (TDD)

**Files:** `application/commands/login.handler.ts`, `domain/errors/{auth-failed,account-locked}.error.ts`, test.

The handler:

1. Lookup user by `(tenant_id, lower(email))`.
2. If not found OR `verify(password)` fails → increment `failed_login_attempts`; if >= LOCKOUT_THRESHOLD within window → set `locked_until = now() + LOCKOUT_DURATION`; throw `AuthFailedError` (generic).
3. If `locked_until > now()` → throw `AccountLockedError` (still maps to 401 with same code `auth.failed` in the controller — no information leak).
4. On success: reset `failed_login_attempts` to 0; create new session row + refresh token; return `{ accessJwt, refreshToken, sessionId }`.
